Carpet Receiving identity safety
- New Carpet Receiving Roll # is checked against the device cache immediately.
- Before stock is applied, Roll # is also checked against live warehouse_records.
- A stale browser cannot create or overwrite an existing cloud carpet identity.
- Manufacturer Roll # is checked against the live carpet set at final receiving validation.
- If live cloud cannot be reached, Completed Carpet Receiving is blocked; draft work can be kept.

Conflict safety
- Existing record-level conflicts remain protected by Build072.
- Build120 automatically clears only no-op conflicts whose queued business payload already equals the current live cloud record (ignoring sync-only timestamps/metadata).
- Divergent device/cloud records are never auto-selected or deleted and remain for explicit review.
