## TestFlight information draft

### Beta App Description

RUNLU Warehouse OS is a local-first warehouse operating system designed primarily for flooring and building-material businesses. This beta focuses on inventory, carpet rolls and cuts, receiving, purchase orders, transfers, shipping, returns, samples, barcode/OCR scanning, local role-based users, and encrypted customer-owned backup and restore.

V1 does not require a RUNLU-hosted warehouse account. Operational data remains on the device unless the tester explicitly exports an encrypted backup through the system save/share flow.

### What to Test

Please test the complete local warehouse workflow:

1. Create a Company, local Owner username/PIN, and Warehouse.
2. Keep the default Flooring / Building Materials template.
3. Add fictional products and inventory.
4. Test receiving / PO, transfer, shipping, return, sample, and carpet roll/cut workflows.
5. Confirm cut allowance defaults to Off / 0 and can be configured by the customer.
6. Test barcode/OCR scanning and local warehouse voice input.
7. Create Manager / Staff / Viewer users and confirm role restrictions.
8. Create an encrypted backup, sign out, restore the backup, and sign in again.
9. Confirm the app remains usable after closing/reopening while offline.

Do not use real customer, supplier, employee, PO, or production data in beta testing.

## Apple processing / TestFlight facts to remember

- A first uploaded build must finish Apple processing before it appears in App Store Connect.
- App Store Connect associates the uploaded build using the bundle ID and version in the app bundle.
- External TestFlight distribution requires Test Information, including a Beta App Description and Feedback Email.
- The first external-testing build requires TestFlight App Review; later builds for the same version may receive a lighter review.
- Apple currently allows up to six builds to be submitted for TestFlight App Review in a 24-hour period.

## Export compliance — do not guess

RUNLU Warehouse OS creates encrypted customer backups using AES-GCM and derives backup keys with PBKDF2. Apple requires an export-compliance determination for apps that use encryption, including standard algorithms or operating-system cryptography.

Before the first TestFlight upload is cleared for external testing:

- answer Apple’s App Encryption / export-compliance questionnaire in App Store Connect;
- follow the result Apple gives for whether documentation is required;
- only after that result is known, set `ITSAppUsesNonExemptEncryption` appropriately in the final Info.plist;
- if Apple requires documentation and supplies an export-compliance code, add `ITSEncryptionExportComplianceCode` as instructed.

Do **not** hard-code `ITSAppUsesNonExemptEncryption = NO` merely to skip the questionnaire.

Official references:

- https://developer.apple.com/help/app-store-connect/manage-app-information/overview-of-export-compliance
- https://developer.apple.com/help/app-store-connect/manage-app-information/determine-and-upload-app-encryption-documentation
- https://developer.apple.com/documentation/bundleresources/information-property-list/itsappusesnonexemptencryption
